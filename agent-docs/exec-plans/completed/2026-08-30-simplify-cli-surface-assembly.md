# Simplify CLI surface assembly

Status: completed
Created: 2026-08-30
Updated: 2026-08-30

## Goal

- Remove the assistant-engine build's reverse dependency on the workspace CLI.
- Give release packing and hosted-runner assembly one explicit, deterministic
  post-build owner for the assistant CLI surface artifact without changing the
  artifact schema, bytes, or runtime CLI discovery behavior.

## Success criteria

- `@murphai/assistant-engine` build only cleans and compiles TypeScript.
- The post-build assembly command accepts no defer, launcher-preference, or timeout
  controls and fails clearly unless the current workspace CLI build exists.
- Release packing and hosted-runner workspace assembly invoke that same generator
  after their topological builds.
- Manifest execution remains bounded in time and output, and runtime callers keep
  their existing source/PATH/built fallback order.
- Focused assistant-engine, runner-bundle, release package-shape, typecheck, build,
  and CLI artifact verification pass.

## Scope

- In scope:
  - assistant-engine CLI manifest reading and artifact generation
  - assistant-engine package build ownership
  - release publishable assembly
  - hosted-runner workspace artifact assembly
  - focused tests for strict built-workspace ownership and artifact shape
- Out of scope:
  - runtime adaptive CLI discovery and assistant reply behavior
  - CLI manifest/schema contents or the generated artifact schema
  - unrelated release-script coverage changes owned by open PRs #2522 and #2559
  - deployment, release publication, ReviewGPT, or PR readiness

## Constraints

- Technical constraints:
  - preserve the exact generated JSON serialization and same-source CLI snapshot
  - preserve bounded child-process timeout, output capture, and teardown
  - introduce no new framework, dependency, or package-layer back-edge
- Product/process constraints:
  - use the repository execution-plan and Frog workflows
  - edit only in the designated task worktree and only via `apply_patch`
  - commit with the approved authenticated GitHub identity and open a draft PR

## Risks and mitigations

1. Risk: a caller runs assembly before the CLI build exists.
   Mitigation: resolve only `packages/cli/dist/bin.js` and report a stable,
   actionable missing-build error before spawning.
2. Risk: moving generation changes provider-visible CLI guidance.
   Mitigation: retain the same full manifest, contract builder, schema version,
   JSON formatting, and newline; compare generated bytes before and after.
3. Risk: a strict build path accidentally replaces adaptive runtime discovery.
   Mitigation: add a separate strict reader for assembly and keep runtime launcher
   selection source/PATH/built in its existing order.
4. Risk: a slow or noisy child hangs or exhausts memory.
   Mitigation: keep one owner-defined finite timeout, existing output caps, and
   TERM/KILL teardown; remove only caller overrides.

## Decisions

- Make one root-owned script the sole assembly command and keep the existing
  assistant-engine generator as a non-executable library function. The command
  must own both the higher-layer CLI input path and lower-layer artifact output
  path; placing that cross-package coordination in assistant-engine would retain
  the reverse ownership edge this task removes.
- Give strict assembly its own built-workspace manifest reader so ordinary runtime
  reads retain their adaptive discovery contract.
- Keep the release-sized five-minute timeout inside the strict assembly owner;
  callers cannot weaken or extend it.
- Keep root `pnpm build` plus assembly inside one host-verification slot so the
  built CLI snapshot cannot be replaced between compilation and artifact write.
- Derive runner build-only inputs from the CLI dependency closure whenever the
  runtime needs assistant-engine, including reduced bundle assembly; packaging
  still uses the independently reduced runtime closure.
- Update the three stale assertions in the release coverage audit even though
  open PR #2522 also owns that file. Its current patch touches different regions;
  disclose the same-file overlap for landing coordination.
