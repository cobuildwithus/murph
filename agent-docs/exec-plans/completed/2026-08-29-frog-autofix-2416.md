# Resolve Codex-managed worktree destinations

Status: completed
Created: 2026-08-29
Updated: 2026-08-29

## Goal

- Let the sanctioned worktree helper derive a repository-scoped destination
  beneath the active Codex home even when `CODEX_HOME` is absent from the task
  shell, without changing the existing explicit-path interface.

## Success criteria

- One explicit helper mode derives the standard current-user Codex home fallback,
  creates only the managed worktree directories it owns, and never interprets an
  unset variable as the filesystem root.
- The mode fails closed for relative homes, unsafe leaf names, foreign-owned or
  unwritable roots, and symlink escapes.
- Focused executable proof covers the unset-variable regression and the validated
  explicit-home path while the existing helper suite remains green.

## Scope

- In scope: `scripts/create-worktree`, its existing storage-guard test owner, and
  the current local-storage lifecycle documentation.
- Out of scope: Codex Desktop environment injection, legacy Frog execution,
  worktree retirement, and any other Frog issue or branch.

## Constraints

- Technical constraints: preserve the existing explicit target form; do not
  change process `HOME`; use the current helper's reservation, storage,
  Spotlight, registration, and rollback owners after destination resolution.
- Product/process constraints: keep private paths and user identifiers out of
  repository artifacts; keep the PR draft until exact-head review and focused
  proof are complete.

## Risks and mitigations

1. Risk: a convenience mode could silently escape the managed Codex root.
   Mitigation: accept one safe leaf, canonicalize each existing directory, and
   fail before branch creation if ownership, writability, or containment fails.
2. Risk: changing positional parsing could break existing callers.
   Mitigation: add an opt-in flag and leave the current explicit-path grammar
   unchanged.

## Tasks

1. Capture a failing regression with `CODEX_HOME` absent and a synthetic normal
   home.
2. Extend the existing helper with one validated Codex-managed destination mode.
3. Document the invocation at the existing checkout-lifecycle owner.
4. Run focused tests, shell syntax validation, diff/privacy review, commit, and
   draft PR workflow.
5. Complete routed exact-head ReviewGPT/CI and land only if every automation gate
   permits it.

## Decisions

- The repository-owned `scripts/create-worktree` helper remains the sole setup
  owner. No wrapper, persisted configuration, or environment mutation is added.
- The managed mode takes one leaf name and derives the repository child itself,
  avoiding caller-controlled relative traversal.
- Destination resolution runs under the helper's existing creation lock, so
  directory preparation and Spotlight marking share the same serialization
  boundary as worktree admission.
- Changelog is not applicable because the change is internal developer tooling
  and does not alter member-visible Murph behavior.
