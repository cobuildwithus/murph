# Reduce doc gardening CI overhead without changing findings

Status: completed
Created: 2026-10-21
Updated: 2026-10-21

## Goal and invariant

Reduce the existing required doc-gardening command's processing time while preserving its discovered inventory, index coverage, broken-target findings, diagnostics, and failure controls. The existing wrapper and report module own this behavior; no new authoritative state, dependency, CI lane, or cache is needed.

## Scope and ranking

1. Implement doc-gardening index matching in Node. Initial local profile: 36.573 seconds, versus 0.666 seconds for docs drift. The upstream Bash loop compares each discovered document to every index row before the existing Node pass filters historical and untracked files. Set membership plus literal directory-prefix checks removes that repeated shell work.
2. Investigate repository-tool test cost separately. The parent reports 121 seconds in CI; the sibling test-pruning task owns test selection and deletions. This change adds composed parity proof and does not remove tests.
3. Retain the merged compiler work and current trust boundaries. The parent reports 68 seconds of cold typechecking and 8 seconds of compilation. Any further build-product reuse needs separate cache-validity and diagnostic-equivalence proof.
4. Leave native compilation/publication with its existing owner. The parent reports 49m22s of Rust compilation inside a 55m54s native budget run because base tags were missing. This task neither duplicates that build nor removes its benchmark.

The initial artifact-hygiene probe failed at a sandbox-denied tsx IPC socket and is not a valid performance sample. Focused verification retries use the authorized executor boundary.

## Implementation

Preserve the upstream native `find` discovery and `sort -u` locale semantics. Use the existing Node report module for exact index-set membership, directory-prefix coverage, target type checks, and report generation. Reuse the existing tracked-file/exclusion filters and output formatter. Preserve the shell entrypoint, CLI flag, and environment failure controls. Do not edit package manifests, workflows, check admission, or test policy.
