# Prepare secure media readers before enabling new sends

Status: completed
Created: 2026-10-21
Updated: 2026-10-21

## Goal and scope

Land the consumer-first prerequisite for common image, audio, video, and document
file delivery. Existing outbox readers and cleanup must recognize those files
before a later release starts creating new-format approval intents.

## Design and risks

- Extend the existing MIME map, verified read, and cleanup paths without new
  state or provider methods. Keep the existing send formats at the request entry
  point with a temporary legacy-extension gate.
- A new media checkpoint restored by a pre-compatibility runner could be rejected
  on retry or have its generated bytes pruned. Complete reader convergence before
  removing the writer gate; never roll back below this reader floor afterward.
- New sends continue to reject unsupported types before adoption or approval.
  Existing PDF/document/ZIP approval, byte hashes, destinations and retries stay
  unchanged. This release has no new member-visible send capability.

## Tasks and verification

1. Reuse common-media MIME/provider and active-vs-terminal cleanup regressions.
2. Prove new-format verified reads while new sends remain rejected with no
   approvals, outbox writes, or consumption of the generated source.
3. Run focused tests, assistant-engine typecheck, complexity and parent review.
4. Document release order, close plan, open prerequisite PR and run final review.

## Product UX and proof boundary

Existing sends retain their behavior. Synthetic future descriptors prove reader
compatibility, not a production send. The following writer PR owns real-Codex
media approval and unsupported-format recovery journeys. No deployment is run.

## Results and parent review

- Five focused test files: 151 tests passed, including unchanged document/ZIP
  sends, provider MIME acceptance, verified new-format reads, active generated
  media retention, terminal cleanup, and Telegram byte-preserving documents.
- The reader-only matrix rejects new saved/generated media before approval or
  source adoption, preserves original bytes and empty outbox, and rejects changed
  bytes when reading a persisted descriptor. Existing schema fields are reused.
- Assistant-engine typecheck passed. Complexity guard passed with unchanged debt
  8 and max 25 in vault-file-send; its request orchestration and signature checks
  remain at their existing owners. Focused request/read tests were rerun after
  extracting the temporary guard and all 59 passed.
- Diff and privacy review passed. No dependency, migration, new state, network
  request, initial prompt, tool schema, or delivery limit changed.
- Deployment and live member receipt are deliberately outside this local proof.
  The separate writer release must wait for deployed reader convergence.
