# Upgrade hosted Codex CLI to 0.149.1

Status: completed
Created: 2026-08-25
Updated: 2026-08-25

## Goal

- Upgrade every live repository owner of the hosted Codex CLI from 0.147.0 to
  0.149.1 while preserving the app-server protocol, provider-egress boundary,
  and base/app runner image coupling.

## Success criteria

- The package manifest, lockfile, runner base build argument, runner base-image
  tag contract, deployment documentation, egress inventory, and runtime
  verification profile all identify Codex 0.149.1.
- The pinned upstream egress inventory is freshly reviewed against the official
  `rust-v0.149.1` source tag and its commit/tree identity is recorded.
- Focused app-server, egress, container-image, dependency-policy, and relevant
  typecheck proof passes locally.
- The exact pushed candidate passes preliminary specialist review, final
  ReviewGPT, and required PR CI.

## Scope

- In scope: exact Codex package/platform pins; hosted runner base/app image
  contract; app-server compatibility comments/tests; provider-egress source
  inventory; runtime verification profile and consumers; deployment notes.
- Out of scope: unrelated dependency upgrades, feature work, deployment itself,
  or compatibility redesign without evidence of an upstream protocol change.

## Constraints

- Technical constraints: the native CLI, the TypeScript development package,
  all optional platform packages, the immutable base-image tag, and the
  runtime verification profile must move together. The provider allowlist must
  remain fail-closed and source-auditable.
- Product/process constraints: keep the change dependency-only unless upstream
  evidence requires adaptation; use exact pins; retain the existing pnpm
  lifecycle-script policy; use draft-first PR workflow; run ReviewGPT beside CI
  on the exact pushed head.

## Risks and mitigations

1. Risk: an upstream route or app-server envelope changes across the two minor
   releases.
   Mitigation: diff the official tags, regenerate/inspect live schema output,
   update only demonstrated compatibility owners, and run focused protocol and
   egress tests.
2. Risk: the runner app layer references a base image with a different Codex
   binary.
   Mitigation: update the Dockerfiles, image contract, tests, and deployment
   documentation atomically; deploy/build the new base before the matching app
   image and recycle warm containers immediately.
3. Risk: the npm package brings an unexpected package or lifecycle change.
   Mitigation: inspect manifest/lockfile deltas and run dependency guard, audit,
   and ignored-build validation.

## Tasks

1. Enumerate all live 0.147.0 owners and compare official Codex 0.147.0 and
   0.149.1 source/schema behavior.
2. Update exact pins, source identities/routes, runtime profile, image contract,
   tests/comments, deployment documentation, and the lockfile.
3. Run focused compatibility, container-contract, dependency-policy, and
   typecheck proof; review the complete diff for scope and privacy.
4. Create an exact-head candidate commit, push it, open the draft PR, and make
   it ready once focused proof and parent review pass.
5. Run preliminary specialists and final ReviewGPT concurrently with CI,
   address any permitted findings, close this plan through `finish-task`, and
   leave the PR in a reviewable green state.

## Decisions

- Use 0.149.1 because the official OpenAI changelog and the npm `latest`
  dist-tag independently identify it as the latest stable Codex CLI release on
  2026-08-25.
- Preserve exact version pins and the existing six optional platform package
  owners; do not broaden version ranges.
- Keep the existing provider route inventory: the official 0.149.1 source diff
  adds no provider HTTP route consumed by the hosted runner. Classify the two
  new printable binary candidates explicitly: turn-cost polling belongs to the
  separate ChatGPT analytics origin, while the extended whoami token is a
  linker-adjacent false positive rather than a literal route.
- Retain the current app-server request/readers unchanged beyond their pinned
  version comments. The 0.149.1 experimental JSON schema still accepts every
  field Murph sends, preserves the canonical JSON-RPC envelope and token-usage
  shape, and the real binary protocol/egress tests pass.
- Treat the binary upgrade as a provider-input surface and measure it rather
  than inferring zero from unchanged Murph prompt source. Identical direct and
  group fixtures show only Codex-owned generated guidance and client metadata
  changes; Murph-authored instructions and schemas are unchanged.
- Retain the version-coupled custom-inference profile hard cut. A read-only
  production aggregate found zero hosted inference connection rows, so there
  is no existing selected state to migrate or recover through new UI. This
  rejects the ReviewGPT stale-profile recovery finding as unreachable in the
  current production state.
- Accept the ReviewGPT coverage finding in a contract-focused form: the real
  pinned-binary test asserts the first Responses request contains the base
  instruction once, the member prompt once, and the expected `web__run`
  declaration. Do not pin Codex's internal 30-second yield wording.
- Classify the two Linux-only scanner candidates as concatenated binary false
  positives. Neither adds a provider route or expands the egress allowlist.
- Update the physical-note deferred-discovery proof to require zero request-byte
  overhead, which is the observed 0.149.1 behavior while the recovery tool
  remains absent until explicit discovery.
