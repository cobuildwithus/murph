# PR 465 ReviewGPT Round 52

## Goal

Resolve both Round 52 findings with the smallest architecture that improves the
actual guarantees: keep the provider deadline active through response-body
consumption and reject redundant co-located signing machinery.

## Constraints

- Preserve the single database transaction that owns the exact delivery attempt.
- Preserve exact production-project/environment OIDC as the sole web-to-Worker
  credential; a shared secret in the same project cannot prove the database
  claim or prevent replay.
- Add no signing schema, secret rotation, claim/reconciliation stage, queue,
  retry, manager, or timeout configuration.
- Keep the provider/web/Temporal deadline ordering at 30/40/55/60 seconds.

## Working Set

- `packages/assistant-engine/src/assistant/channels/runtime.ts`
- focused Telegram channel tests and the PR description

## Verification Plan

- Add a streamed Telegram response-body deadline regression test.
- Run focused owner tests, owner typechecks, diff coverage, required
  security/privacy and coverage-write audits, exact-head CI, and another Mountain
  ReviewGPT round.

## Progress

- Round 52 checked PR #465 at `865abf3900ca0562b8b530717417caf762e646a8`
  with GPT-5.6 Pro and returned two High findings.
- Static tracing confirmed both cited implementation facts: the simplification
  pass removed the signed authority envelope, and the provider timeout was
  cleared after response headers rather than after the response body. The threat
  model below rejects the first fact as a vulnerability.
- Trust-boundary tracing rejects the authority finding: the exact Vercel project
  is the documented source-of-truth plane, and a co-located secret gives code in
  that same plane no capability it does not already have. Restoring the removed
  HMAC schema would add deployment and rotation machinery without proving the
  database claim or preventing replay.
- The provider request helper now owns response-body parsing before releasing its
  30-second abort signal. Abort-driven parse failures remain ambiguous; malformed
  non-abort JSON keeps the existing null-payload behavior.
- The one-use payload helper, unused custom headers/method parameters, duplicate
  text/photo/voice body reads, and unused operation generality were deleted. The
  production change removes two more lines than it adds.
- A deterministic streamed-429 regression failed before the fix and now passes:
  headers arrive at 29 seconds, the body would arrive at 31 seconds, and the
  provider attempt aborts once at 30 seconds without retrying.
- The assistant channel runtime file passes 38 tests and the assistant-engine
  typecheck passes. Dependency, workspace-boundary, hosted architecture, logging,
  and all affected owner/reverse-dependent typechecks also pass.
- The broader reverse-dependent test lane passed 1,491 assistant-runtime tests
  but hit six unrelated scheduler/temp-directory races. An isolated rerun
  reproduced five without traversing Telegram; exact-head CI remains the
  clean-host gate for those known timing-sensitive tests.
- Required security/privacy, coverage-write, and minimality reviews found no
  unresolved issue and added no further machinery.
