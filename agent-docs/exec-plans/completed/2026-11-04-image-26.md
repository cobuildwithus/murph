# Upgrade image generation to GPT Image 2.6

Status: completed
Created: 2026-11-04
Updated: 2026-11-04

## Outcome and invariant

Upgrade the existing generation and reference-edit path to GPT Image 2.6 Flare.
Preserve exact image reply provenance, historical captures, delivery authority,
request formats, bounded errors, and usage accounting.

## Evidence and decisions

- The November 4 OpenAI changelog releases 2.6 Flare and Sunburst:
  https://developers.openai.com/api/docs/changelog
- Flare preserves the existing interactive generation role; adding a model
  selector or switching editing to Sunburst is outside this version upgrade.
- Both existing Images endpoints remain supported:
  https://developers.openai.com/api/docs/models/gpt-image-2.6-flare
- Pricing remains text input $5, cached text $1.25, image input $8, cached
  image $2, and image output $30 per million tokens:
  https://developers.openai.com/api/docs/pricing
- Existing output formats and quality settings stay unchanged. SVG, animation,
  and explicit complexity controls are separate product work.

## Owners and deployment

The image adapter owns the provider model. The response-media predicate owns
capture recognition. Hosted execution owns the image usage model allowlist;
Web derives prices from it. No new state or external calls are introduced.
Deploy the Web usage reader before new runners. New readers retain old models.
A model-default rollback must retain the reader for persisted 2.6 captures and
usage. No production deployment is authorized by this repository update alone.

## Tasks and proof

1. Update the model, provenance reader, usage allowlist and durable owner.
2. Extend existing request, tool, reply-link, retention and accounting tests.
3. Run focused tests and affected typechecks; review the complete diff.
4. Run the existing real-Codex image continuation journey for the new source.
5. Add the member release note, record evidence, and make a scoped commit.

Product UX journeys: create an image; edit using reference images; reply to
current and historical captures; retain capture evidence after outbox pruning;
apply the exact capture as an avatar only after a later authorized request.
No prompt/schema changes or added foreground operations are intended.
