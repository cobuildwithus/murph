## Decisions

- This is an internal reliability correction; no changelog item is expected
  unless the implementation broadens into a member-visible change.
- Coverage and sensitive final-review lenses apply. Frontend and prompt lenses
  do not apply. Product UX remains limited to preserving the already-defined
  foreground-reply recovery contract.
- ReviewGPT's round-3 finding reproduced against the real production path and
  current base. The candidate-101 exception blocked a valid route, and native
  reply resolution also supplied the incoming message ID instead of its exact
  provider reply target to the new priority query.
- Current main absorbed the branch's duplicate session-routing production
  owner. The inspected reconciliation retained the outbox projection, pending
  hint, and executable probes while reducing this PR's production-source diff.
- Provider-message lookup is route-scoped in the existing foreground-tag
  projection. Compound Linq groups reserve up to two candidates for every
  distinct exact anchor before optional route history fills the same 100-intent
  canonical-read cap.
- ReviewGPT round 4 identified the same retention-versus-admission conflict in
  rebuilt legacy-media recovery: a rebuild pessimistically enrolled every
  current token-only image delivery in the 100-candidate compatibility path.
  The product continues to admit more than 100 distinct current generated-image
  identities inside the existing retention horizon; that retained state must
  not become a foreground admission limit.
- Media-sensitive legacy compatibility remains only for callers without an
  exact transport identity. Product-level dedupe tokens and transport-level
  delivery-idempotency keys are independent identities; cron notifications can
  legitimately carry different values. Rebuild indexes the supplied exact
  transport key for every valid retry. Once that exact projected route misses,
  broad media-sensitive recovery cannot legitimately match and must not inspect
  the global legacy candidate set. Callers without exact transport identity
  retain the existing bounded compatibility lookup for pre-migration retries
  whose original key cannot be reconstructed from regenerated media. This
  narrows the existing owner without adding another cap, projection, field, or
  lifecycle.
