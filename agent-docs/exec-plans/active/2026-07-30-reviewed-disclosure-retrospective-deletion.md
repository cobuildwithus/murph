# Reviewed disclosure retrospective deletion

## Outcome

Remove the first-use natural-language acknowledgement gate after ReviewGPT
proved that its authorization parser repeated the same contradiction class,
while preserving automatic reviewed-answer drain and every exact-message,
sender, route, review, expiry, and final-egress authority.

## Retrospective decision

- The original requirement is automatic continuation of a reviewed
  current-sender answer into the originating group.
- First-reviewed authored source was +240/-79; round 2 was +199/-80, a
  42-line net reduction.
- Repeated parser failures came from making one sentence carry both
  deterministic authorization syntax and arbitrary private-subject text.
- Delete the acknowledgement column, migration, parser, protocol status, and
  prompt flow. Do not add another classifier, consent owner, lifecycle, queue,
  or compatibility path.
- Keep the exact accepted group message as the private question and preserve
  the existing server-bound sender/route proof plus outgoing answer review.

## Steps

1. Add pre-change proof that the conforming contrastive refusal reaches the
   acknowledgement write and mailbox append.
2. Delete the first-use acknowledgement/parser/status surface and restore the
   deferred tool-description budget.
3. Update live architecture, product, and protocol docs; preserve immutable
   completed plan snapshots.
4. Run focused Web, hosted-execution, assistant-engine, assistant-runtime,
   typecheck, docs, diff, and privacy proof.
5. Close the plan, push, refresh the PR contract and change shape, rerun CI,
   and start ReviewGPT round 3 with the recorded deletion retrospective.

## Invariants

- The exact accepted group input remains the only private question.
- The server still derives and revalidates current sender, member, identity,
  group thread, route, origin session, request expiry, and egress authority.
- The private answer still passes fresh outgoing review before the group
  output-only continuation receives it.
- A reviewed completion drains without another inbound message and queues one
  reply to the original group message.
- No first-use persisted acknowledgement or incoming semantic classifier
  remains.

## Evidence

- Before deletion, the production Web matcher accepted the conforming
  contrastive refusal and the focused test failed on `true` versus `false`.
- After deletion, the focused current-sender Web file passes 7/7, the
  hosted-execution current-sender parser file passes 4/4, and the two
  assistant tool-description contract files pass 86/86.
