# Prepare shared package release 1.3.3

Status: active
Created: 2026-09-06
Updated: 2026-09-06

## Goal

- Prepare the ordinary shared 1.3.3 package release so private orchestration can consume the already-implemented public mailbox progress and conversation admission contracts and remove temporary duplicate validation.

## Success criteria

- All five release-manifest packages share version 1.3.3; existing dependency policy and release validation pass.
- Existing release notes and changelog describe the source range since 1.3.2.
- Focused package proof, required exact-head CI, and GPT-6 Pro review cover the release preparation candidate.
- The PR is reviewable without publishing a tag or package.

## Scope

- In scope: five package versions, generated release notes and changelog, release validation and PR evidence.
- Out of scope: application changes, new release tooling, private consumer changes, tag publication, npm publication, production migration.

## Constraints

- Reuse the existing shared-version release manifest and tagged GitHub workflow; do not introduce a package-specific release path.
- Preserve exact public-registry dependencies. Private consumers must wait for an actual published artifact.

## Risks and mitigations

1. A release includes all existing source changes since 1.3.2, not only mailbox contracts. Preserve the complete generated source-range notes and require normal release gates before publication.
2. A new public package can remove historical wire fields. Consumer adoption remains a separate reviewed change with historical replay and parser compatibility proof.

## Tasks

1. Verify registry version, tag availability, release workflow, and overlapping PRs.
2. Prepare versions through the existing release helper and generate the ordinary release documentation.
3. Validate the release candidate, inspect its full diff, and open the PR.
4. Run GPT-6 Pro concurrently with required CI; resolve accepted findings.

## Decisions

- Prepare the PR through existing version and documentation helpers. The all-in-one release script also creates and pushes tags, which are separate from preparing this reviewed candidate.
- No new authored JavaScript or TypeScript; no complexity metric or runtime architecture change is needed.

## Verification

- Passed: frozen-lockfile install, release-target validation at 1.3.3, dependency policy, full workspace package build, hosted-execution typecheck, hosted-execution tests (633 tests across 54 files), release artifact secret guard tests (22 tests), and release verification matrix validation.
- Passed: the existing packager produced all five 1.3.3 tarballs and its artifact secret guard accepted all five. The hosted-execution tarball includes the new progress and conversation admission fields and resolves public dependencies to 1.3.3.
- Pending: exact-head CI and GPT-6 Pro. No tag or npm publication has occurred.
