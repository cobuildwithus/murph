# Upgrade hosted Codex CLI to 0.151.0

Status: active
Created: 2026-08-29
Updated: 2026-08-29

## Goal

- Upgrade every live Murph owner of the hosted Codex CLI from `0.149.1` to the
  latest stable `0.151.0` release while preserving the App Server protocol,
  OpenAI egress allowlist, runner image, provider usage attribution, and
  deployment contracts.

## Success criteria

- All executable, package, container, configuration, diagnostic, and test pins
  resolve to exactly `@openai/codex@0.151.0`; immutable historical plans remain
  unchanged.
- The exact upstream tag, commit, source-tree identity, and OpenAI route
  inventory are reviewed and verified from upstream source.
- Murph's App Server parser and real pinned-binary conformance tests accept the
  new protocol, including usage metadata and subagent usage attribution.
- Dependency, type, container-contract, and focused hosted-runtime checks pass;
  the opt-in real-Codex assistant journey is inspected and judged ready.
- A draft PR contains the required runtime/deployment evidence, passes required
  candidate review, and is ready only after focused proof is complete.

## Scope

- In scope: exact CLI/package pins, lockfile, minimum-age exception, runner image
  and deployment diagnostics, upstream egress fixture, App Server boundary
  compatibility, usage-accounting proof, and directly coupled tests/docs.
- Out of scope: changing Murph's product UX, usage-pricing policy, provider
  selection, introducing an App Server compatibility layer without observed
  need, or adopting prerelease `0.152.0-alpha.*` builds.

## Constraints

- Technical constraints: retain one warm native Codex App Server, direct
  requested/served-model attribution into the Web-owned ledger, best-effort
  usage recording off the reply critical path, and exact runner egress source
  verification.
- Product/process constraints: smallest maintainable change, exact-version
  supply-chain controls, guarded worktree, draft-first PR, preliminary
  completion-specialist review, final ReviewGPT review, and broad exact-head CI.

## Risks and mitigations

1. Risk: `0.151.0` changes App Server messages or usage metadata in a way Murph's
   boundary silently drops or misattributes.
   Mitigation: generate the version-matched schema, inspect the relevant diff,
   and run both parser fixtures and real-binary usage/subagent journeys.
2. Risk: upstream OpenAI request paths change and the runner either blocks a
   valid call or permits an unreviewed route.
   Mitigation: derive the exact tag/commit/tree identity, review changed
   `codex-api` sources, update the narrow fixture, and run source plus runtime
   egress conformance.
3. Risk: a stale pin leaves production, diagnostics, or CI on a different CLI.
   Mitigation: inventory all prior-version literals and require no live
   `0.149.1` occurrences outside immutable historical records.
4. Risk: container-only dependencies or sandbox behavior regress despite unit
   tests.
   Mitigation: run the focused runner/container contracts locally and rely on
   the native `linux/amd64` PR gate for the authoritative sandbox proof.

## Tasks

1. Inventory every live pin and resolve `rust-v0.151.0` to its immutable
   upstream source identity.
2. Update exact package, lockfile, image, fixture, diagnostics, tests, and
   version-boundary comments.
3. Compare the generated App Server schema and reviewed upstream request-route
   sources; adapt only where an observed contract change requires it.
4. Run focused protocol, usage, egress, dependency, type, runner, and real-Codex
   verification.
5. Audit the privacy-safe diff, commit and push it with approved identity, open
   the draft PR, complete candidate reviews, and wait for exact-head CI.

## Decisions

- Target `0.151.0`, the latest stable release as of 2026-08-29; do not adopt the
  available `0.152.0-alpha.1` prerelease.
- Treat this as a high-risk hosted-runtime/dependency change because the binary
  owns App Server protocol and provider egress even though no member-visible UX
  change is intended.
- Keep Murph's usage boundary unchanged: the generated
  `thread/tokenUsage/updated` schema is byte-for-byte unchanged from `0.149.1`,
  and the new `rawResponse/completed.usageMetadata` field is additive and does
  not replace Murph's Web-owned token ledger input. Adapt the detached-child
  lifecycle boundary for the new canonical `subAgentActivity.completed` value;
  the initial live Luna journey proved that rejecting it poisons an otherwise
  healthy workspace checkpoint.
- Keep the newly surfaced `/v1/guardian` and `/v1/guardian-classifier` routes
  blocked. They belong to ChatGPT-backed guardian flows that Murph's API-key
  hosted runtime does not enable. Classify the optional
  `/v1/analytics/codex/turn-costs` worker as a separate-origin route that is
  inactive without an OTEL exporter rather than widening the OpenAI allowlist.
- Record the repository audit as baseline debt rather than upgrade-introduced
  debt: `origin/main` and the upgraded lockfile report the same 74 advisory IDs
  and identical severity metadata.
- Retain the version-coupled custom-inference hard cut. A read-only production
  aggregate found zero hosted inference connection rows, so no current selected
  endpoint requires migration, compatibility UI, or a fallback path.
- Treat the CLI bump as a provider-input surface and measure it through the real
  App Server request-capture harness. The complete normalized first request
  grows by 30 `o200k_base` tokens and 86 UTF-8 bytes for both direct and group
  fixtures; all change is Codex-owned metadata, input item IDs, and the Sol
  helper's `ultrafast` service-tier text. Murph-authored instructions and tool
  schemas are unchanged.

  runner image smoke where locally supported; and one focused
  `test:assistant:live` journey after deterministic proof.
- Expected outcomes: every command passes, generated-schema inspection reveals
  no unhandled required message shape, usage remains requested/served-model
  attributed including subagents, and the live assistant reply is useful and
  truthful.
- Completed evidence:
  - upstream tag/commit/tree and ten reviewed source paths verified;

  - App Server egress/schema conformance passes (10 tests), including the exact
    installed-binary token-usage and subagent-lifecycle schema;
  - focused assistant usage/runtime suites pass (205 tests), Cloudflare
    runner/egress suites pass (313 tests), hosted Web profile suites pass (161
    tests), and hosted-control suites pass (66 tests);
  - relevant assistant, runner, hosted-control, hosted-execution, and Web
    TypeScript lanes pass.
