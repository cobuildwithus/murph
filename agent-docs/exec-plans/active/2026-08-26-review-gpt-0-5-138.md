# Update ReviewGPT to 0.5.138

Status: active
Created: 2026-08-26
Updated: 2026-08-26

## Goal

- Make Murph consume the published ReviewGPT 0.5.138 release so its PR review
  wake flow receives the validated-rehydration tab cleanup fix.

## Success criteria

- The root manifest and lockfile resolve `@cobuild/review-gpt` 0.5.138 from the
  public npm registry.
- Murph's ReviewGPT wrapper can invoke the installed release.
- Dependency policy, ignored-build review, focused tooling tests, and typecheck
  pass; the audit introduces no advisory beyond the exact pre-change baseline.
- Required ReviewGPT and exact-head PR checks resolve with no accepted findings.

## Scope

- In scope: the ReviewGPT dev-dependency declaration, lockfile resolution,
  exact-version minimum-release-age exception, its release-audit assertion, and
  the task execution-plan record.
- Out of scope: Murph product/runtime behavior, ReviewGPT source changes, browser
  tab mutation outside ReviewGPT's own validated cleanup path, and deployment.

## Constraints

- Technical constraints: public-registry package only; update manifest and
  lockfile together; preserve pnpm build-script policy; use Node 24.14.1+.
- Product/process constraints: isolated worktree and PR; no user-facing Product
  UX change; keep ReviewGPT and CI on the same exact pushed candidate head.

## Risks and mitigations

1. Risk: an unexpected transitive dependency or lifecycle-script change enters
   through the package bump.
   Mitigation: inspect the lockfile delta and package metadata, then run Murph's
   dependency guard, high-severity audit, and ignored-build review.
2. Risk: Murph's wrapper is incompatible with the released CLI.
   Mitigation: run the wrapper/preflight focused tests and direct CLI help smoke,
   then dogfood the release through the required ReviewGPT passes.
3. Risk: review results are attached to a stale PR head.
   Mitigation: push a scoped candidate, launch review and CI from that exact SHA,
   and repeat the gate only after a PR-authored correction changes the head.

## Tasks

1. Update `@cobuild/review-gpt` to 0.5.138 in the root manifest and lockfile.
2. Move the existing minimum-release-age exception to exactly 0.5.138, then
   inspect package provenance, dependency delta, and lifecycle-script policy.
3. Run dependency, focused wrapper, direct CLI, and typecheck proof.
4. Commit and push the candidate, open the PR, and launch required ReviewGPT
   passes concurrently with exact-head CI.
5. Resolve findings, perform final parent review, archive this plan, and push the
   final exact head.

## Decisions

- Treat this as a high-risk dependency/configuration change under repository
  policy even though ReviewGPT is a development-only tool.
- Product UX, prompt, and frontend lenses are not applicable; the preliminary
  specialist pass uses the coverage/direct-proof lens.
- Keep the 24-hour release-age floor intact and move only the existing exact
  ReviewGPT exception to 0.5.138 because this release was built, fully tested,
  tagged, and published through trusted publishing during this task.
- Do not broaden this bump to existing dependency-audit debt: candidate and
  pre-change baseline both report exactly 6 low, 37 moderate, 34 high, and 1
  critical advisory, with the same ReviewGPT-path advisory set and no transitive
  lockfile change.
