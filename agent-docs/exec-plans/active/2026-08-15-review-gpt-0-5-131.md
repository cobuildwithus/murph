## Goal

- Adopt the latest published ReviewGPT package for subsequent repository review gates.

## Success criteria

- The root dependency, supply-chain exception, installed package, and lockfile resolve `@cobuild/review-gpt` 0.5.131.
- The exact-version regression test guards both manifest seams.
- Focused dependency verification passes and the pushed PR head is reviewed with the updated package.

## Scope

- In scope: dependency metadata, lockfile, exact-version test, and this execution plan.
- Out of scope: Murph production behavior, ReviewGPT implementation internals, browser-lane policy, prompts, UI, and deployment configuration.

## Constraints

- Use the public-registry package tagged `latest` at update time.
- Keep lockfile movement limited to ReviewGPT's direct resolution.
- Do not use the unavailable Eragon browser lane.
- This is internal review tooling, so no member-facing changelog entry applies.

## Risks and mitigations

1. Risk: installation changes unrelated dependency resolutions.
   Mitigation: update only ReviewGPT and inspect the complete manifest and lockfile diff.
2. Risk: a completed review targets the older PR head.
   Mitigation: treat the earlier review as stale and start the next required review from the exact pushed dependency-update head.
