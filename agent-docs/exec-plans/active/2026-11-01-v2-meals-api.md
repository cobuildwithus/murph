## Outcome and invariants

Ship member-scoped list/detail and queued canonical meal removal for native iOS.
Health truth stays in the vault and existing encrypted replica/mailbox. Reads
never wake the runtime; no images, provenance, or new durable health store.

## Owners and implementation

- Add a versioned structured Meals section to the Browser Vault core projection,
  preserving canonical timezone, stable IDs, nullable nutrition and complete days.
  Existing canonical lifecycle/revision selection remains authoritative.
- Companion native auth plus existing Browser Vault authority gates protect reads
  and removal. Validate cursors; return distinct missing/unavailable errors.
- Extend the closed member-action union with meal deletion and dispatch directly
  through deleteMealRecord to the canonical lifecycle tombstone. No assistant turn.
- New Web accepts only a Meals-capable replica before queueing the new action;
  old/missing projections fail closed. New runtime publication establishes the
  compatible runtime rollback floor. Deploy Web on merge, then runtime.
- Original manual phone upload UUID is not retained (only a member-bound hash).
  Return null, document the smallest possible future addition, do not build it.
