# Hospital connector expectations

Last verified: 2026-11-27

Web owners below are in `apps/web/src/lib/clinical-records/` unless qualified. Web test names omit `apps/web/test/` and `.test.ts`. Clinical suite names also omit the `clinical-records-` prefix. Package owners use paths under `packages/<package>/src/`. The runtime clinical suite is `packages/assistant-runtime/test/hosted-runtime-clinical-records.test.ts`. “Covered” means an executable assertion at the named boundary. “Partially covered” identifies the unproved part. Synthetic Epic transport exercises local behavior. Vendor qualification requires separate evidence.

## Qualification still missing

- Oracle readers support saved grants, v1 scopes, tenant-specific query shapes and the egress switch. Oracle writer and exact sandbox registration must precede a public lifecycle. Search visibility, new-start admission and egress have separate controls (`oracle-integration.ts:oracleSearchEnabled`, `oracleStartsEnabledFor`, `oracleEgressDisabled`; oracle and retrieval tests).
- Epic qualification runs through `pnpm clinical:sandbox-proof --vendor epic`. On 2026-11-27 headless runs completed consent, import, restart refresh, repeat import, daily sync and disconnect for `fhircamila` and `fhirderrick`. Their family bands in `apps/web/scripts/epic-proof/policy.ts` are about 0.5x to 2x those measured counts, because the sandbox drifts weekly. Requested families measured at zero allow up to five. FamilyMemberHistory and MedicationStatement, which Epic retrieval never requests, must stay at zero. Every band requires one Patient. `fhirdesiree` is unmeasured and keeps provisional bands from Epic's published chart description. `fhircamila` downloaded, parsed and queued eight documents. Both imports end partial and limited by the hospital: Epic's sandbox marks some vital-sign Observations and note DocumentReferences as suppressed (OperationOutcome code 59204, plus 59134 on summaries). That is sandbox data that is not released to the patient, not a registration gap: the Murph Dev registration already carries the same 44 APIs as the production registration, including Vital Signs and Clinical Notes (only Observation.Search (Flowsheets) is absent, as on the newer production registration). Treat partial as expected in the sandbox. Epic omits `meta.lastUpdated`. Before #5437 each repeat or daily import superseded every unchanged record in place with an empty change receipt; an unchanged reread now writes no revision. The local proof observes importer decisions, attachment parsing and queued enrichment from the restored vault. A vendor outage, login block or band miss requires another authorized qualification window before rollout.
- athena, eClinicalWorks and Greenway profiles await implemented connectors and verified registrations. Vendor lifetimes, Greenway count limits, eCW format parameters and DSTU2 are future contracts. Vendors without a sandbox require a separately authorized restricted pilot.
